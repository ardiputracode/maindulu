Konfigurasi singular tetap didukung dan digabung/dedup; Host/Origin dan CSRF tetap divalidasi, cookie `Secure` mengikuti origin setiap request, dan HTTP jaringan tetap memerlukan opt-in LAN tepercaya. Verifikasi: **603 tes unit/integrasi**, build, dan **183 tes browser backend** lulus, termasuk proxy TLS lokal nyata; tunnel/domain produksi tidak diklaim telah diuji.
- Mode folder bersama RomM/maindulu (skema 18, opt-in `MAIN_DULU_EXTERNAL_WRITABLE=true`): upload admin dan scan memakai root ROM/BIOS yang sama; Hapus admin juga menjadwalkan penghapusan file fisik sumber. Kuota/free-space mencakup storage bersama dan staging. Overlay `deploy/docker-compose.shared.yml`, warning UI, migrasi dari read-only, dan [panduan Portainer](doc/koleksi-folder-bersama.md) ditambahkan. Default sumber eksternal tetap read-only tanpa opt-in; bukan sinkronisasi database RomM.
- Koleksi ROM/BIOS eksternal read-only (skema 17): env runtime `MAIN_DULU_EXTERNAL_ROM_DIR` / `MAIN_DULU_EXTERNAL_BIOS_DIR`, scan manual admin tanpa salin/upload ulang, pemetaan terpisah dari storage internal, proteksi DELETE/cleanup/recovery, serta validasi perubahan sumber sebelum ETag/download. Scan ulang byte identik menyambungkan file aktif yang hilang/dipindah ke ID lama tanpa mengganti metadata/save. Overlay Compose dan panduan migrasi Portainer tersedia; metadata/cover RomM tidak diimpor. [Panduan dan batas verifikasi](doc/koleksi-eksternal-read-only.md).

Verifikasi: **559 tes unit/integrasi** (termasuk 9 baru `rom-converto`, 8 `CHD policy`, 14 `CHD worker`, 2 `backup schema 14→15`), build, **browser E2E CHD serial** lulus. ### Diubah

- Sesuai keputusan pengguna 2026-11-03, backup byte ROM/BIOS/cover dikeluarkan dari MVP; Milestone 7 menjadi backup metadata/save, deploy, dan dokumentasi. Katalog berisi data tidak lagi memblokir backup akun/save; restore bersih memerlukan upload ulang aset bila ingin bermain. Ini bukan klaim kesiapan produksi/container/HTTPS atau pemulihan koleksi lengkap.
- Pengaman historis Milestone 2: format 1 skema 8 mensyaratkan tabel/aset katalog kosong. Pada Milestone 3 syarat itu berlaku pada skema 9 beserta koordinasi upload/cleanup. Pengaman tersebut tetap berlaku untuk **verify/restore format 1 lama**, tetapi backup baru memakai format 2 metadata saja. Untuk skema 6 gunakan aplikasi lama terlebih dahulu; sumber backup tidak dimigrasikan otomatis.
- Setelah Milestone 3, capability `gameCatalog`/`biosCatalog` menjadi `true` untuk API, lalu dipakai UI pada Milestone 4–5. Recovery apply offline membersihkan koordinasi upload/cleanup mati; backup format 2 hanya membersihkan koordinasi pada snapshot, tidak pada sumber.

### Diperbaiki

- Assertion regresi Library/progres/autosave memakai kontrak `saveIdentity` (`core-SHA256`) yang sudah ada, bukan ID katalog; runtime identitas save tidak diubah. Pencatat tes cache membaca header akhir `writeHead` agar metadata HEAD/304 yang dikirim langsung oleh Fastify tercatat bersama byte body server.
- Race gate data lock Windows saat penghapusan file masih pending mengembalikan `EPERM`, bukan `EEXIST`. Retry khusus Windows tetap terbatas pada jendela lama dan hanya masuk setelah exclusive create berhasil; permission failure permanen, namespace asing, lease aktif dan maintenance tetap fail-closed. Tes injeksi dan 20 pengulangan publikasi katalog lintas proses lulus. Tidak mengubah skema, engine, format save, atau identitas game.
- Regresi browser save: aktifkan tab yang sedang diuji, kurangi input CPU redundan dengan snapshot konflik tetap berbeda, tutup engine tab yang tidak diperlukan, dan gunakan handler DOM nyata pada toolbar native yang auto-hide sambil tetap menunggu persistence IndexedDB. Tidak menaikkan timeout/menambah retry atau mengubah runtime player/save untuk meluluskan tes.
- Koneksi pemeriksaan metadata backup ditutup sebelum koneksi snapshot SQLite asinkron dibuat, agar lifecycle statement/iterator/GC tidak memakai koneksi worker backup. Tes snapshot multi-halaman dengan GC paksa dan pengulangan browser backup/save ditambahkan/dijalankan, tanpa menaikkan timeout atau melonggarkan data lock. Hasil dan percobaan timeout awal dicatat di `doc/backup-metadata-katalog.md`.
- Sinkronisasi tes regresi browser save: verifikasi checksum tersimpan menggantikan teks status sementara, snapshot konflik dua tab dibuat benar-benar berbeda tanpa bergantung revisi awal tetap, konflik otomatis tidak menunggu klik tombol yang sudah dinonaktifkan, event toolbar menghindari race auto-hide/canvas, dan pembacaan state tamu menunggu write IndexedDB. Tidak mengubah runtime player/save atau batas keamanan untuk membuat tes lulus.
